How the numbers are calculated
  • Raw call-log files (columns like Agent Name, B Party No, Record1, Total Duration(In Seconds)):
    • Calls dialed = number of log rows for that agent (each row is one dial attempt, identified by the B Party No column).
    • Responded = rows where Record1 holds an actual recording link. Rows marked "No Voice" / blank are not counted as responded.
    • Total duration = sum of "Total Duration (In Seconds)" for the responded rows only, converted to minutes.
    • Avg talk time (sec) = that same seconds total ÷ number of responded calls.
    • Response rate = responded ÷ dialed × 100.
  • Pre-summarised sheets (columns already named Name / No. of Call dialed / No. of responded / Avg talk time / Total Duration) are used as-is.
  • Everything above is plain arithmetic run in your browser — no AI model, no data sent anywhere.
Notes on hosting this on GitHub Pages
  • No backend, so no AI is possible here — GitHub Pages only serves static files. This page uses formula-based analytics instead of a model; that's the right fit for pure static hosting.
  • Data never leaves the browser. Files are parsed locally with SheetJS; nothing is uploaded. Still, don't commit real call reports into the public repo — only commit the tool itself.
  • Public by default. Free GitHub Pages sites are reachable by anyone with the URL (private Pages needs GitHub Enterprise).
  • Vendor the libraries for reliability. This page loads SheetJS and Chart.js from cdnjs pinned to fixed versions. For long-term use, download both files into your repo so the tool still works if the CDN is blocked.
  • Large files: everything runs client-side, so very large exports (tens of thousands of rows) may be slow — fine for daily/weekly reports like these.
  • Theme choice follows your system preference by default and can be toggled with the button top-right; it resets on reload since the page stores nothing.
